# TPD Add-in — Architecture

This is a module-level map of the add-in as of the `v2.3.0` release, organized by the same `@Folder("TPD_Addin.X")` grouping used in Rubberduck's Code Explorer and in the `/src` export layout. For the developer workflow (how to change, export, build, and release), see [CONTRIBUTING.md](../CONTRIBUTING.md).

## Overview

The add-in exposes one custom ribbon tab ("TPD") with two groups, defined in `customUI/customUI14.xml`:

- **Sheet Tools** — EQ Count, and the picker (custom) paths: "Create Customer EQ List", "Create Customer Schedule", "Split Sheet by Column", plus "Save Each Sheet to XLSX".
- **Defaults** — the one-click paths ("EQ List", "Schedule", "Split Sheets" — run a flow straight from saved defaults, no picker) beside the large "Set TPD Defaults" button.

Ribbon buttons call thin wrapper subs in `modRibbonCallbacks`, which delegate to the feature modules described below. Startup (`modStartup.InitializeAddIn`) runs from `RibbonOnLoad` and stamps the running version into the registry-backed preference store. Saved settings live in the Windows registry per user (`modPreferences`), not in the workbook. The hidden `_Resources` sheet and its embedded default-logo shape come from the base `.xlam`, not from code.

## Naming: "header" vs. "heading"

The word "header" has two unrelated meanings in this codebase, so the naming convention splits them:

- **`header`** — the TPD title block at the top of a sheet (`EQUIPMENT LIST` / Customer / Project / PM / Date / Rev), e.g. `InsertEQHeaderBlock`, `InsertDefaultCustScheduleHeader`.
- **`heading`** — the column heading row of the data table, e.g. `headingsRow`, `headingList`, `colHeading`, `GetHeadingList`, `FindHeadingIndex`.

A third case, the logo's positioning anchor row in `modHelpers_Logo`, is neither — it's called `anchorRow` since it can point at either a title-block row or a heading row depending on the caller. Use these names for any new code; don't reintroduce `header`/`headerRow` for column-heading concepts.

## TPD_Addin.EQList

| Module | Purpose |
|---|---|
| `modMain_CustEQList` | Customer EQ List flow. `CreateCustEQList_Internal` (picker path) shows `CustEQListColumnPickerForm`; `CreateCustEQListFromDefaults_Internal` (one-click "EQ List" button) skips the picker, resolving columns from `PREF_EQLIST_COLUMNS` → shipped default via `ResolveColumnList`, then `HeadingsPresentOnSheet` to keep only those that exist on the source (bails with a message if none do). Both hand off to `CreateCustEQList_DoWork`, which copies all rows to a new `Customer EQ List` sheet **before** any formatting, deletes unselected columns, formats, inserts the EQ header block + embedded default logo (`InsertDefaultLogo … "right-top"` — [#82](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/82)), and freezes panes. |
| `modMain_CountEquipmentRows` | "EQ Count" entry point. `RunCountEquipmentRows` → `WithPerformance PERF_COUNT_EQ_ROWS` → `CountEquipmentRows_Internal` (validates the active worksheet via `RequireActiveWorkbook`) → `NumberEquipmentRows` inserts an `EQ COUNT` column and numbers every row except those marked `PARENT` or `INCLUDED` in the Purchased column, with leading-zero formatting sized to the highest number. A row with a blank Purchased value is a real equipment line whose status isn't filled in yet, so it is numbered by design ([#6](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/6), closed as working-as-intended). |
| `CustEQListColumnPickerForm` | UserForm for choosing which columns to keep when creating a Customer EQ List. `LoadColumns` builds the checkbox grid (`modHelpers_CheckboxLayout`) then checks the resolved selection — `ResolveColumnList(Array(PREF_EQLIST_PICKER_COLUMNS, PREF_EQLIST_COLUMNS), DefaultEqListColumns())` → `ApplyColumnSelection` (shared with the split picker — [#81](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/81), [#96](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/96)); no inline default array any more ([#98](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/98)). OK writes the picker-only `PREF_EQLIST_PICKER_COLUMNS` key (not the shared Set-TPD-Defaults key) after checking at least one column is ticked (`HasColumnSelection` — [#104](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/104)). Controls: `fraColumns`, `cmdOK`, `cmdCancel`, and the design-time title label `lblCustEQListTitle` (the [#82](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/82) `txtImgPath` / `cmdBrowse` / `lblSelectLogo` vestiges were removed in the VBE). |

## TPD_Addin.Schedule

| Module | Purpose |
|---|---|
| `modMain_CustSchedule` | Customer Schedule flow ([#112](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/112)) — the schedule twin of `modMain_CustEQList`. `CreateCustSchedule_Internal` (picker path, "Create Customer Schedule" in Sheet Tools) shows `frmCustScheduleColumnPicker`; `CreateCustScheduleFromDefaults_Internal` (one-click "Schedule" in Defaults) resolves columns from `PREF_SCHEDULE_COLUMNS` → shipped default via `ResolveColumnList`, then `HeadingsPresentOnSheet` (bails with a message if none of the default headings are on the source). Both call `CreateCustSchedule_DoWork`: copy all rows to a new `Customer Schedule` sheet **before** any formatting, drop unselected columns, `FormatEQSheet wsNew, 1, "Tasks"`, `AutoFitUsedColumns`, `InsertDefaultCustScheduleHeader` (header rows + Date text + logo in one call), then `SafeFreezePanes` at `SCHEDULE_HEADER_ROW_COUNT + 1`. |
| `frmCustScheduleColumnPicker` | UserForm for choosing which columns to keep — its `.frx` is a byte-clone of `CustEQListColumnPickerForm.frx`, so the title label (`lblCustEQListTitle`) carries the EQ caption in the binary and `UserForm_Initialize` retexts it to "Customer Schedule Generator" at run time ([#114](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/114)). `LoadColumns` builds the grid then `ApplyColumnSelection` with `ResolveColumnList(Array(PREF_SCHEDULE_PICKER_COLUMNS, PREF_SCHEDULE_COLUMNS), DefaultScheduleColumns())`; OK writes the picker-only `PREF_SCHEDULE_PICKER_COLUMNS` key after the `HasColumnSelection` guard. |

The header builder `InsertDefaultCustScheduleHeader` (+ `SCHEDULE_HEADER_ROW_COUNT`) lives in `modHelpers_SheetSetup`. The `modMain_CustSchedule` placeholder that was removed in [#48](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/48) is now the real module; "Default Schedule Header" (`modMain_CustScheduleHeader`) was removed in [#96](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/96).

## TPD_Addin.SplitExport

| Module | Purpose |
|---|---|
| `modMain_SplitSheets` | Split-sheet flow. `SplitSheetByColumn_Internal` (picker path) prompts via `splitSheetByColumnOptionsForm`; `SplitSheetByColumnFromDefaults_Internal` (one-click "Split Sheets" button) skips the picker, resolving the group column from `PREF_SPLIT_GROUPCOL` and columns from `PREF_SPLIT_COLUMNS` (each → shipped default) via `ResolveGroupColumn` / `ResolveColumnList`. Both call `SplitSheetByColumn_DoWork`, which creates or clears one sheet per unique value in the group column and copies matching rows in (it messages and bails if the group column isn't on the sheet). |
| `modMain_ExportSheets` | "Save Each Sheet to XLSX" entry point. Prompts for a filename suffix/date via `frmFilenameOptions`, then saves each eligible worksheet to its own `.xlsx` in a per-workbook export folder. `ShouldExportSheet` skips `_`-prefixed internal sheets and very-hidden sheets always, and plain-hidden sheets unless the source-level `EXPORT_INCLUDE_HIDDEN_SHEETS` flag is turned on ([#8](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/8)). Per-sheet failures are collected and reported in one summary rather than aborting the run ([#15](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/15)). |
| `modHelpers_Export` | Creates/locates the export folder next to the workbook, named after the workbook file (`EnsureExportFolder`; returns `""` after a message if the workbook is unsaved or the folder can't be made), and copies a single worksheet out to its own `.xlsx` file (`ExportSheetToXLSX`, returns `""` on success or a reason string on failure). If a sheet's target name collides with an already-open workbook it gets a ` (export)` suffix; an existing target file on disk is overwritten without prompting ([#64](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/64)); any `SaveAs` failure is caught, the temporary `ws.Copy` workbook is closed without saving, and the reason is returned ([#15](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/15)). `ReportBatchOutcome` is the shared end-of-run summary box ("N done" + a list of `'name': reason` failures) used by both the Split and Export flows. |
| `splitSheetByColumnOptionsForm` | UserForm for choosing the group-by column and which columns to keep when splitting a sheet. `LoadColumns` builds the grid, checks the resolved column selection (`ResolveColumnList(Array(PREF_SPLIT_PICKER_COLUMNS, PREF_SPLIT_COLUMNS), DefaultSplitColumns())` → `ApplyColumnSelection`), populates the group dropdown, then `SelectGroupColumn` selects the resolved group value (`ResolveGroupColumn(Array(PREF_SPLIT_PICKER_GROUPCOL, PREF_SPLIT_GROUPCOL), DefaultSplitGroupColumn())`), matching on the `NormalizeCellText` compare form of both sides so a whitespace-dirty saved preference still resolves ([#103](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/103)); falls back to the first column if not found (the "Vendor" literal is gone — [#98](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/98)). `cmdOK_Click` validates both the group column and (via `HasColumnSelection`) that at least one column is checked ([#10](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/10)), then writes the picker-only `PREF_SPLIT_PICKER_*` keys ([#96](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/96)). |
| `frmFilenameOptions` | Small UserForm for appending free text and/or today's date to exported filenames. |

## TPD_Addin.Preferences

| Module | Purpose |
|---|---|
| `modPreferences` | Per-user key/value preference storage in the Windows registry via `SaveSetting`/`GetSetting` (`HKCU\Software\VB and VBA Program Settings\TPD_Addin\Preferences`). Registry rather than a sheet inside the `.xlam` because Excel never saves an add-in on exit, so in-workbook writes were silently lost on quit ([#84](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/84)). `SavePref`/`LoadPref`/`DeletePref` plus `SaveColumnList`/`LoadColumnList` for comma-separated column lists; a missing key returns the caller's default. `ResolveColumnList(keys, fallbackCsv)` / `ResolveGroupColumn(keys, fallback)` walk a caller-supplied key array in priority order and return the first non-empty saved value, else the shipped default — the pickers pass `Array(LastUsed*, DefaultUser*)`, the one-click flows pass `Array(DefaultUser*)` ([#96](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/96)). Generic multi-key helpers: `SavePrefs` (write an array of key/value pairs, returns `False` if any write failed, no rollback) and `AllPrefsUnset` (True iff every listed key reads back empty). Also the Set TPD Defaults dialog support: `NormalizeColumnList` (tabs/CR/LF → `, `, drop empties, keep dupes), `CollapseWhitespace` (a header name's compare form — tabs → spaces, then delegates to `modHelpers_Strings.NormalizeCellText`), `SaveAllDefaults` and `DefaultsNeverSaved` — thin callers of `SavePrefs`/`AllPrefsUnset` over the one shared list of the four dialog keys ([#102](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/102)). |
| `modPreferences_KeyMap` | Central list of every preference key so keys never float as loose string literals. Column defaults are three layers ([#96](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/96)): **shipped** (`modPreferences_Defaults`, no key); **user one-click** — the `DefaultUser*` keys (`PREF_EQLIST_COLUMNS`, `PREF_SCHEDULE_COLUMNS`, `PREF_SPLIT_COLUMNS`, `PREF_SPLIT_GROUPCOL`), written **only** by the Set TPD Defaults dialog, read by the one-click buttons; **user picker** — the `LastUsed*` keys (`PREF_EQLIST_PICKER_COLUMNS`, `PREF_SCHEDULE_PICKER_COLUMNS`, `PREF_SPLIT_PICKER_COLUMNS`, `PREF_SPLIT_PICKER_GROUPCOL`), written by the picker forms on OK. Pickers resolve `LastUsed*` → `DefaultUser*` → shipped; one-click resolves `DefaultUser*` → shipped. Plus `PREF_VERSION`. |
| `modPreferences_Defaults` | The hard-coded shipped column lists (`DefaultEqListColumns`, `DefaultScheduleColumns`, `DefaultSplitColumns`, `DefaultSplitGroupColumn`), comma-separated. The single source: they seed the dialog's first run, back its per-page "Restore defaults", are the value `LoadPref` returns for an unsaved key, and are the final `ResolveColumnList` / `ResolveGroupColumn` fallback for both the pickers and the one-click flows ([#98](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/98) — the pickers no longer carry their own arrays). |
| `modPreferences_Initializer` | `InitializePreferences` — stamps `PREF_VERSION` with `ADDIN_VERSION` when it changes (support/diagnostics). No value seeding: `LoadPref` returns the caller's default for any unset key. |
| `modMain_SetTPDDefaults` | "Set TPD Defaults" ribbon entry point. `RunSetTPDDefaults` shows `frmSetTPDDefaults` modally; `ClearTPDDefaultsStatusBar` is the `Application.OnTime` target that wipes the save confirmation (must be a standard-module sub — `OnTime` can't call into a form). |
| `frmSetTPDDefaults` | The "Set TPD Defaults" dialog ([#25](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/25), [#94](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/94)). MultiPage (`mpgPages`) with EQ List / Schedule / Split Sheets / Logo tabs. Each column tab is a MultiLine TextBox of plain comma-separated header names, normalized on paste (Ctrl+V caught on `KeyUp`) and on `Exit`; per-tab "Restore defaults" resets from `modPreferences_Defaults`. OK blocks with a message if any of the three column-list fields is empty (an empty list is never meaningful — every consumer reads it as "use the built-in defaults" — so "Restore defaults" is the way to get the built-in list; the Split group-column field is allowed empty — [#104](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/104)), then `SaveAllDefaults` → status-bar confirm (no MsgBox on success); a write failure keeps the form open with a `vbCritical` box. Cancel / Esc / title-bar X all discard silently. The Logo tab is a static note that the header logo is embedded in the add-in; `imgLogoPreview` stays empty — a working preview needs a real shape-to-`Picture` mechanism (the removed `PastePicture` stub never worked) and is folded into the user-settable-logo work ([#95](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/95) / [#109](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/109)). `lblVersion` shows `ADDIN_VERSION` (#94). |

## TPD_Addin.Helpers

Shared utilities used across more than one feature area.

| Module | Purpose |
|---|---|
| `modHelpers_Workbook` | Sheet/workbook utilities: `RequireActiveWorkbook` (the standard "bail with a message if no workbook is open" guard), `GetFirstVisibleSheet` (guards no-workbook / no-visible-sheet, returns `Nothing`), create-or-clear a sheet by name, next available sheet name, last-row (`GetLastRow` — last row with content in *any* column, `Find`-based, safe on an empty sheet; the "end of the data table" helper, vs a per-column `.End(xlUp)` which you use only when you mean that one column — [#89](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/89)) / last-column lookups, and `IsWorkbookOpen(fileName)`. |
| `modHelpers_Headers` | Reads a worksheet's heading row into an array; finds a heading's column index. `FindHeadingIndex` defaults to a right-to-left scan so the authoritative "Vendor" column wins over decoy columns; pass `preferRightmost:=False` for a plain left-to-right lookup ([#45](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/45)). |
| `modHelpers_Columns` | Collection-membership helper; deletes columns not in a selected-headings list; `HeadingsPresentOnSheet` returns the subset of a wanted list that actually appears on a sheet's heading row (the one-click flows use it so a default list that matches nothing doesn't delete every column — [#96](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/96)); gets unique values in a column; `CopyFilteredRowsByColumns` copies matching rows across sheets projected onto a column selection (data only — formatting is the caller's job); `CopyEntireSheetRows` copies every row verbatim (whole-row copy carries row grouping across). |
| `modHelpers_Strings` | String sanitizing helpers: `SanitizeSheetName`, `SanitizeFileText`, and `NormalizeCellText` (first physical line, NBSP→space, collapsed spaces, trimmed — used wherever cell values are compared or deduped). |
| `modHelpers_SheetSetup` | Header-block construction: `InsertEQHeaderBlock` (the EQ title block; the Customer EQ List flow adds the logo + freeze separately) and `InsertDefaultCustScheduleHeader` (the schedule title block + Date text + logo in one call, used by the Customer Schedule flow). Owns `EQ_HEADER_ROW_COUNT` / `SCHEDULE_HEADER_ROW_COUNT`, `InsertRows`, and `GetTodaysDate`. |
| `modHelpers_SheetFormatting` | Formats generated EQ / schedule / split sheets (borders, alignment, fonts), freezes panes, autofits used columns. `FormatEQSheet(ws, headingsRow, leftAlignHeading)` centres every column except `leftAlignHeading` (default `"Description"`; the schedule flow passes `"Tasks"`), which keeps its natural left alignment. |
| `modHelpers_Logo` | Positions and resizes the embedded default logo: `InsertDefaultLogo` (horizontal/vertical alignment keywords, optional scale-to-max-rows) and `ResizeImageToMaxRows`. `DefaultLogoShape` is the single place the `_Resources` / `DefaultLogo` names are resolved — returns `Nothing` on a broken base file, and `InsertDefaultLogo` raises a clear error rather than a cryptic subscript one ([#105](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/105)). The non-functional `PastePicture` clipboard stub was removed in #105 (its only caller, the Set TPD Defaults logo preview, never rendered — a real preview mechanism is part of [#95](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/95) / [#109](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/109)). The file-path `InsertLogoAtRight` / `SafeInsertLogoAtRight` pair was removed in [#82](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/82) — the Customer EQ List flow now uses `InsertDefaultLogo` like every other logo caller. |
| `modHelpers_CheckboxLayout` | Builds the checkbox grid shared by both column-picker forms — one box per heading, 3 columns filled top-to-bottom. When there are more headings than fit in 3 columns at the preferred height, the columns grow taller (never a 4th column off the right edge) and the frame gets a vertical scrollbar so every box stays reachable ([#47](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/47)). |
| `modHelpers_CheckboxSelection` | Reads which checkboxes are checked into a `Collection` (`GetSelectedColumns`), tests whether any are checked (`HasColumnSelection`), re-checks boxes matching a column list (`AutoSelectColumns`), and `ApplyColumnSelection(fra, resolved)` — checks exactly the boxes in `resolved`, a list the caller has already run through `modPreferences.ResolveColumnList` (both pickers call it after building the grid — [#81](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/81), [#96](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/96)). |

## TPD_Addin.Core

Add-in lifecycle and infrastructure — not directly user-facing.

| Module | Purpose |
|---|---|
| `modPerformance` | `WithPerformance` wrapper: disables `ScreenUpdating`/`EnableEvents` and sets manual calculation around a named internal routine, then restores them afterward. On an error inside the wrapped routine, `CleanUp` still restores all three settings and then surfaces `Err.Description` in a `MsgBox` ([#7](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/7)). The routine is selected by a `PERF_*` string constant passed by the ribbon callback, so a mistyped name fails to compile rather than hitting the `Unknown action` branch at run time ([#36](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/36)). The Customer EQ List / Schedule / Split flows each contribute a picker `PERF_*` and a one-click `PERF_*_DEFAULTS` constant + `Case` ([#96](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/96), [#112](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/112)). |
| `modStartup` | `ADDIN_VERSION` constant + `InitializeAddIn`, called from `RibbonOnLoad`; runs `InitializePreferences` (registry version stamp). (`_Resources` + the embedded logo come from the base `.xlam`; the code-side fallback `modResources` was removed in [#62](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/62).) |
| `modExport_VBAModules` | The VBA export macro `ExportAllVBAModules` that supports the source-control workflow itself. |

For "does this sheet exist in the add-in", use `SheetExists(ThisWorkbook, name)` from `modHelpers_Workbook` (the old single-purpose `modHelpers_Diagnostics.SheetExists2` was removed in [#50](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/50) — no callers, and it did nothing `SheetExists` didn't).

### Regressions to guard against (all fixed — don't undo them)

- **`modPerformance.WithPerformance` ([#7](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/7) / [#36](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/36))** — the `CleanUp` handler must **always** restore `ScreenUpdating` / `EnableEvents` / `Calculation`, or they stay broken for the Excel session on any error. Callers pass a `PERF_*` constant, not a bare string.
- **Never call a `Sub` as `MySub (obj)` ([#29](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/29))** — the parens force by-value evaluation (the default property), so a `Worksheet`/`Workbook` argument raises run-time 438. Use `MySub obj` or `Call MySub(obj)`. The `Split Sheet by Column` loop ([#32](https://github.com/srjohnson1986/TPD-Addin-XLAM/issues/32)) now reports per-value failures in its summary, so a regression there is at least visible.

For the full history of fixed defects (EQC-10, GEN-04, EXP-07, SPL-11, CORE-01, EXP-08, CEQ-06, UI-01, #29–#68), see `CHANGELOG.md`.
